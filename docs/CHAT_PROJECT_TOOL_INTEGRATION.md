# 聊天与项目工具整合

日期：2026-10-29。当前为本地实现，尚未提交或部署。

## 产品体验

聊天和本地项目的输入区共用“工具”入口。面板分为“已连接”和“发现开源工具”。

- 已连接：选择本次对话可用的 MCP 工具，明确只读或需要确认；最多选择 20 个。
- 项目命令：明确绑定一个服务端执行工作区；新版 Windows 客户端还可另行选择本机命令目录。
- 调用结果：显示在对话中。项目对话会将真实工具返回送回下一次模型步骤，继续处理原任务。
- 操作确认：服务端 MCP 写入和 CLI 生成持久操作预览；项目内可确认、取消，并继续根据结果处理。普通聊天确认后展示实际执行结果。
- 停止：阻止新的项目步骤；本机进程停止，已经送出的远端操作需要核对执行记录。
- 工具选择按登录账号和项目保存于当前浏览器会话。目录能力令牌只在内存保存，不写入历史或发送服务器。

工具面板沿用现有靛紫色语义变量、Lucide 图标、输入区和执行过程组件。使用原生模态对话框管理焦点与 Escape 退出。移动端面板限制宽度和高度，内容单独滚动。

## 开源能力来源

| 项目 | 接入方式 | 用途与依赖 | 上游许可 |
| --- | --- | --- | --- |
| [GitHub MCP Server](https://github.com/github/github-mcp-server) | Streamable HTTP，账号专用凭据，默认只读 | 仓库、Issue、PR；需要 GitHub 授权 | MIT |
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | stdio，固定 `@playwright/mcp@0.0.83`，headless、isolated | 网页操作；需要 Node.js 18+、浏览器和操作系统依赖 | Apache-2.0 |
| [Fetch](https://github.com/modelcontextprotocol/servers/tree/main/src/fetch) | uvx，固定 `mcp-server-fetch==2026.10.24` | 网页正文；官方参考实现，部署者需控制出站访问 | MIT |
| [ripgrep](https://github.com/BurntSushi/ripgrep) | 已安装的 rg 可执行文件，结构化参数 | 工作区内字面文字搜索 | MIT / Unlicense |
| [GitHub CLI](https://github.com/cli/cli) | 已安装、已授权的 gh | Issue 与 PR 列表查询 | MIT |

另外复用 Git 与项目已有的 npm、pytest、Maven 测试入口。第三方代码不复制进业务源码。接入预设保存为停用连接，健康检查和工具发现成功后才启用；缺少依赖或凭据不标记成功。

## 执行边界

`ToolSelection` 包含 `mcpToolIds`、`workspaceId`、`localCli`。用户身份只取 Java 的认证会话。Python 再次按用户读取工具和工作区，模型不能提交用户身份、权限或确认标志。

服务端固定提供六类项目命令：Git 状态、Git 差异摘要、源码搜索、GitHub Issue、GitHub PR、项目测试。搜索参数作为字面值，不能指定任意路径；测试只允许选择 npm、pytest、Maven，不能提交任意脚本。

服务端命令使用现有工作区规则、审计与持久确认操作，确认时复核目录绑定。项目步骤禁止在同一轮重复外部调用；拒绝后不重新请求同名工具。

本机命令由 Electron 主进程执行。渲染进程不能指定任意命令和目录，只持有原生目录选择器授予的临时令牌。IPC 验证可信来源、顶层页面和所属窗口；页面导航后撤销令牌。测试和 GitHub 网络查询在原生窗口另行确认。命令有 60 秒上限、输出长度限制和进程树终止。

浏览器选定的文件目录与命令目录分别授权；执行位置会显示给用户和模型，不能把远端测试称为本机测试。浏览器版仍无法直接执行本机终端命令。

## MCP 会话

持续连接按用户、服务端 ID、对话标识和配置摘要隔离，串行处理每个连接上的工具调用。上限 32 个连接、单连接队列 8 项、空闲 5 分钟回收。初始化 30 秒、工具调用 60 秒、调用者等待 90 秒。调用结果未知时不自动重放。关闭服务会回收连接，配置或凭据变化建立新连接。

此进程内会话池适用于当前单 worker 部署。多 worker / 多实例部署需要对话粘性路由或集中 MCP 网关；不保证跨进程和服务重启保留浏览器状态。

## 部署准备

1. 同步更新 Vue、Java、Python。现有数据库已包含 MCP、CLI 和待确认操作表，无新增迁移。
2. 服务端工具环境可在 Compose 构建时设置 `INSTALL_AGENT_TOOLS=true`，安装 Git、ripgrep、GitHub CLI、Node/npm、uv。默认构建保持原配置。
3. Playwright 还需要安装其匹配的 Chromium 和操作系统依赖。运行环境准备好后，在面板点击“接入并检查”。该检查证明 MCP 传输和工具发现成功，不代替浏览器操作验收。
4. 为每个使用 GitHub MCP 的账号配置单独变量 `LYLE_GITHUB_MCP_<用户ID>`，值为 `Bearer ` 加该账号的令牌。不要在聊天、源码或前端配置中粘贴令牌。预设不使用全站共享 GitHub 凭据。此版未实现 OAuth 授权向导。
5. 服务端 gh 使用服务进程的凭据。多人环境优先使用账号独立的 GitHub MCP，或在用户自己的 Windows 客户端使用 gh；不要向公共服务进程注入能访问所有用户仓库的管理员令牌。
6. 本机命令需要重新构建、安装 Windows 客户端，并在本机安装所选命令依赖。此功能不能仅通过更新网页生效。

预览入口：前端 `artifacts/tool-integration-2026-10-29/preview.html`。此入口有明确示例标识，使用真实 UI 组件和隔离的接口替身，不会访问真实仓库、运行命令或申请登录权限。
