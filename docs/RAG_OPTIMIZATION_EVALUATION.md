# RAG 第二批优化评测

评测日期：2026-09-12。真实现有规则、默认不重排的 50 题对照中，新旧每题 Recall@5 和 MRR 均一致，关键词 CPU 重复扫描显著减少。这支持在保留 legacy 融合的同时启用基础优化；尚不足以默认启用 RRF、自适应查询或宣称实际回答质量不下降。以下是本机离线检索回放，生产用户看到的 28～34 秒还包含 embedding、网络、辅助模型等开销，不能用这份 CPU 结果直接预测完整回答耗时。

## 固定语料与证据

- 固定集：`tests/fixtures/rag_evaluation_v1.json`，50 题、40 个片段、12 份文档，44 题有答案、6 题无答案或授权范围内无答案。
- 分组：直接问答 10、同义问法 7、多轮缺指代 5、精确数字/版本 9、多段/多文档 6、无答案 5、知识库隔离 5、重复片段 3。
- 语料是人工编写的虚构“星桥”产品与运维手册，不是生产知识库。每项 ground truth 是能在原文中找到的完整事实片段，并附允许命中的片段位置；相同文字的重复位置可以作为同一事实的替代证据。
- SHA-256：`12cd7ae7265158ec60aa5adc54ca75567fda420da286a7cc1e1cf32c77cf8f15`。该文件在新策略比较前冻结，未根据新旧结果修改标准答案。
- 校验同时检查 `doc_id`、`chunkIndex`、`startChar`、`endChar`、原始片段和知识库授权范围。元数据明确带有知识库 ID 时，必须与实际来源一致；不能仅凭同名标题认定引用正确。

多轮题保留了 `conversation_history`，但本次检索回放输入仍是原始当前问题，没有把期望答案或历史中的实体偷偷加进检索词。它因此也能暴露缺指代尚未解决的情况。

配置：Top K=5、每次检索候选上限 18、全局重排上限 40、父子段扩展开启/相邻段最多 2、并行数 4，自适应关闭、辅助模型关闭。主要对照保留 `rerank_enabled=false`，另设显式开启词法重排的对照组。当前代码默认 `rag_optimized_retrieval_enabled=true`、`rag_fusion_mode=legacy`、`rag_adaptive_retrieval_enabled=false`、`rag_auxiliary_model_enabled=false`；关键词索引也能在关闭新检索管线后独立工作。本次显式打开词法重排的变体不意味着生产默认已开启模型重排。

测量环境：Python 3.12.13，Windows 11 / 10.0.26200；最终测量开始于 `2026-09-12T12:57:03.685523+00:00`。

代码排查还发现旧 query rewrite / sufficiency prompt 中示例 JSON 花括号未转义，模板格式化失败后会走回退路径。本轮修复模板，同时新增 `rag_auxiliary_model_enabled=false`，避免修模板意外增加默认网络调用。此处离线回放没有验证真实辅助模型的延迟或质量。

## 指标定义

- Recall@5：每题所需证据组在前 5 条中的覆盖比例，再对 44 条有答案题取平均。重复位置命中同一事实只贡献一次。
- MRR：首个相关来源的倒数排名，在有答案题上取平均。
- 全部事实有证据支持：所有人工指定事实都能在返回的正确来源原文中找到的题目比例。这是生成前的证据可用性，**不是实际回答或引用正确率**。
- 来源位置有效：实际返回片段可以精确定位回冻结原文；授权范围外命中另计泄漏。
- 无答案候选率：6 条没有可用答案的题里，检索仍返回内容的比例。返回候选不等于生成模型编造答案；拒答质量需要实际生成后独立评审。
- 查询延迟 p50/p95：50 条固定问题的本机检索耗时分位值。CPU 压测每个规模分别测一次冷查询和 3 次热查询，热查询 p95 只是这 3 个样本的插值，不能用作生产 SLO。

查询固定为“星桥知识库文件备份保留几天”。在 40 个原始片段外扩展带常见词的无关附录至 100/200/300 段；没有更改正确证据。旧/新每个规模的 Top 5 位置与顺序相同，冷/热查询结果也一致。

## 保留的坏例和限制

- R013“为啥相关程度很高还是没答全？”：固定管线旧实现相关证据第 1，新实现第 2；R014“检索时整库一遍遍扫太费时怎么办？”：第 1 降到第 3。它们仍在前 5，但表中的 MRR 回退是真实存在的，没有以总召回相同掩盖。
- R011、R015、R016、R035 首个相关来源排名改善，综合后管线 MRR 仍从 0.906061 降至 0.899621。因此“只改变性能、完全不改变排序”并不适用于全局重排这部分。
- R015“找不到依据时可以猜资料里的金额吗？”：默认关闭重排时，新旧都没有在前 5 条找回“不能凭空补充文档中的数字”的证据，不能把该题算对。
- R021“具体改了什么？”：新旧都漏掉前文提到的 2.4.1 变更事实，召回的是其他包含泛化词语的段落。去重、倒排和并行不能替代多轮指代解析。
- R038～R042 及 R045 没有授权范围内的答案，仍返回候选。必须单独评估生成是否准确表述证据不足，不能通过“有检索结果”认定问题已解决。
- 语料小且合成，TF-IDF 与关键词分支的词法特征接近；词法 reranker 也不是生产语义重排模型。结论不覆盖扫描 PDF/OCR、超长文档、真实多语言数据、外部数据库、生产负载或并发更新质量。
- 自适应策略关闭，没有证明“先单查、判断充分就省掉后续查询”的回答质量。在真实 embedding 与辅助模型评测前，不建议默认开启。

## 实际生成对照

`tests/fixtures/rag_paired_generation_input_v1.json` 提供 9 题的新旧实际规则、默认不重排的真实检索结果。先选 6 类代表题，再追加在补充重排回放中观察到回退的 R013/R014 与缺指代失败 R021，用于敏感回归诊断；这不是随机样本，不能给出整体回答准确率保证。

生成调用仅应收到 `question`、`history` 和所选 `baseline_contexts` / `optimized_contexts`。`review_only` 中的期望事实只能在生成结束后用于独立评审，不得拼到生成 prompt。若没有把 history 提供给模型，R020/R021 的评审也必须明确模型缺少会话历史。

主任务已使用现有 provider 的 `qwen/qwen3.5-flash` 完成 9 × 2 次实际生成，原始结果在 `tests/fixtures/rag_generated_answers_v1.jsonl`，逐题审阅在 `tests/fixtures/rag_generated_answer_review_v1.json`。18 次都有正文、以 `stop` 结束，无错误或重试。配置为 temperature=0、输出上限 768 token，使用现有 `lyle-agent-v1` prompt，旧/新交替先后调用。模型确实收到了历史、问题和对应检索正文，白名单排除了 `review_only`。输出记录的 `input_sha256` 是按键排序后的 JSON 对象 hash，不是原始文件字节 hash；已按生成脚本相同方法重算匹配。

这次**仅为评测临时关闭 Qwen thinking**，没有更改生产配置。此前保持默认 thinking 的尝试里，11 次输出预算被推理消耗、正文为空且以 `length` 结束，原始记录保留在 `tests/fixtures/rag_generation_thinking_probe_v1.jsonl`；随后停止重复尝试。该 probe 不计入有效回答质量/延迟比较，不能删掉这次失败后声称默认推理模式也已验证。生成脚本已增加遇到空正文、长度截断或错误即停止的保护。

## 复现与回归

在 `ai-service-python` 目录运行（本机 Python 运行时为 `.venv-win/Scripts/python.exe`）：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
.venv-win/Scripts/python.exe scripts/benchmark_rag_optimization.py --baseline-root C:/Temp/lyle-rag-baseline-l19tdrbe --sizes 100 200 300 --repeats 3 --output tests/fixtures/rag_optimization_results_v1.json --paired-generation-output tests/fixtures/rag_paired_generation_input_v1.json
.venv-win/Scripts/python.exe -m pytest tests/test_rag_regression_evaluation.py -q
```

需要单独重跑旧版时使用 `--baseline-only` 并移除 `--paired-generation-output`。其他机器必须提供同 hash 的修改前 `app/` 快照给 `--baseline-root`，不能把当前代码同时当作新旧实现。

可选生成接口：`--generator your_module:generate --allow-external-generation`。回调签名为 `generate(*, question, history, contexts)`，返回 `{"answer": str, "citations": [{"doc_id": str, "chunkIndex": str, "quote": str}]}`。接口保留真实回答、耗时并检查引用原文是否存在；它不会根据 oracle 生成假回答，也不自动宣称答案正确。使用实际 provider 时需自行配置已授权的模型与额度。没有提供回调时不会触发外部生成请求。

评测回归覆盖冻结集与原文偏移校验、知识库隔离、重复位置证据计数、多事实漏召回、无答案独立分母、生成接口不接收 oracle，以及新关键词索引与冻结旧 Top 5 一致性。
