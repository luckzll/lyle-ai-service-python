# RAG 缓存、追问补全与模型评测

## 本批实现

- 查询向量缓存：默认 300 秒，最多 256 条 / 8 MiB。按用户、会话、实际查询与向量模型配置隔离；写入文档和记忆仍直接向量化。
- 初召回候选缓存：默认 30 秒，最多 128 条 / 8 MiB；不缓存最终答案，不跳过本轮权限验证。并发相同请求共享一次计算，错误、空结果及降级结果不会长期缓存。
- 每次 Java 请求从业务数据库生成知识库授权、有效文件及文件版本清单。删除、权限变动、重建后的下一次请求不能命中旧版本缓存；不同 Python 进程的旧分块也被版本过滤排除。
- 重建生成新文件版本，完成回调只更新对应版本的解析状态。Qdrant 点 ID 包含文件版本；旧任务晚到不会删除或覆盖新任务的向量。
- 多轮追问仅在存在明确回指时读取同一用户、同一会话的短期历史，最多 6 条 / 1200 字；多对象、话题切换、历史不完整时不猜。只使用用户已说出的对象，保留原问题作为检索候选，写作问题不被替换。默认不增加 LLM 调用。
- 提供确定性的分块上下文增强，把文件名、章节和文首显式元数据用于检索；引用仍使用原文及原始位置。修正分块时换行和空白归一化造成的位置偏移。
- 增加 FastEmbed ONNX 交叉编码器重排选项，复用已有依赖，保留原 FlagEmbedding 接口。默认只加载本地模型，避免在线请求等待模型下载。
- 将知识库资料放到提示词较稳定的前部，把当前时间、记忆和问题放在后部。记录供应商真实返回的缓存读取/写入 token；不把“具备复用条件”等同于“已经命中”，不改变现有计价公式。

## 默认启用范围

查询缓存、候选缓存、保守追问补全默认启用。候选缓存只有完整可信清单时才生效。

`RERANK_ENABLED=false`、`RAG_CHUNK_CONTEXT_ENABLED=false`。冻结证据集出现上下文增强召回回退；单独重排保持了证据召回，MRR 从 0.9439 提高到 0.9602，但本机 CPU 检索中位耗时从约 4 ms 升至 1230 ms。鉴于当前优先缩短等待，两项都保留为可配置选项，具体四组消融结果见 [真实向量对比](RAG_CONTEXT_EVALUATION_V2.md)。不能把较小测试集上的排序改善视为所有知识库回答质量都会改善。

`RAG_AUXILIARY_MODEL_ENABLED=false` 保持不变。没有启用 HyDE、每题 LLM 改写、TurboRAG 或进程内向量库迁移。

## 发布与数据兼容

1. 同批发布 Java/Python。Java Flyway V33 为已有文件补 `retrieval_revision=legacy`，与历史 Qdrant 无版本字段兼容。新文件及重建使用独立版本。
2. 带知识库的 HTTP 检索要求服务端生成的完整 `knowledgeScope`。旧 Java 若缺清单会明确失败，不能降级为不校验文件的检索。只升级 Python 或只回滚 Java 不属于兼容组合。
3. 旧知识库不会自动改变向量。只有明确启用分块上下文并执行重建，才会使用增强表示。本批未对现有资料发起批量重建。
4. 缓存仅在当前进程内，重启会清空；多进程通过每次请求携带的业务文件版本保证隔离，不依赖跨进程共享缓存。
5. 旧版本 Qdrant 点保留但对用户检索不可见，避免并发重建互删。后续应按业务当前版本进行定期回收；此批没有部署自动删除任务。

## 验证边界

缓存独立实验（5 组冷/热配对）：真实 BGE 查询向量中位耗时 4.59 ms → 0.10 ms；600 个合成分块、实际关键词召回的候选缓存 57.67 ms → 0.44 ms。命中时模型/召回调用数为 0，返回的原文和引用字段完全一致；变更文件清单会重新召回并排除已删除文件。权限清单在作用域创建时构造为不可变视图，逐段检查不再复制全表。原始样本见 `tests/fixtures/rag_cache_results_v2.json`，复现入口为 `scripts/benchmark_rag_cache_v2.py`。这里没有 Qdrant 网络或生成模型，不代表线上整轮速度。

自动化测试覆盖权限/版本隔离、并发失效、回退、引用原文位置、历史隔离及使用量计量。真实向量与重排实验使用冻结的 50 个问题和证据；本地余弦替代 Qdrant 网络，未调用答案生成模型。它们不能证明线上总耗时或最终生成答案质量已达到某个比例。

部署后应分别检查首段正文时间、知识库分阶段耗时、缓存命中计数、真实模型重排后端、无证据回答及引用正确性，再扩大可选功能范围。
